# 真实反馈

只有老师已经看到稿件并给出修改稿、选择或明确意见时读取。反馈进入写作外循环，不自动重跑生成链。

## 输入

- 本次 `run.json`、`draft.md` 和实际交付内容；
- 老师修改稿、明确选择或原话；
- 可选的场景、渠道和目标说明。

## 处理

1. 先定位变化发生在事实、主线、素材取舍、信息权重还是表达执行。
2. 只记录能从反馈直接观察到的变化，不猜老师未说明的动机。
3. 候选必须写触发条件、不适用范围、证据来源和反例；一次修改不升级成规则。
4. 通过现有 `memory add/confirm/counter/cancel/reinforce/retire` 管理候选；源知识库保持只读。

反馈阶段可以增加 `feedback.json`。除它之外不要复制本次四份运行产物，也不建设改稿编排或版本回退。

如果老师从 `handoff` 后的 `draft.md` 开始修改，以老师版本为准。核验建议只是反馈证据，不自动回写或覆盖老师正文。

## 失败处理

| 触发条件 | 处理 | 仍失败 |
|---|---|---|
| 只有“感觉不对” | 只问一个最能定位决策层的问题 | 保持为本次观察，不晋级 |
| 修改稿与原稿无法对应 | 要求明确版本或段落 | 不推断修改原因 |
| 多位老师反馈冲突 | 按最窄场景分别保留 | 等客户确认或授权负责人裁决 |
