# 默认生成快线

这份文件是生成任务唯一默认加载的运行指导。目标是先交付唯一的完整可修改正文，再做一次受限复核；不要把它重新拆成多个角色或阶段文档。
显式启动后，不调用 Skill 工具，不加载其他 Skill、斜杠命令或品牌写作助手；即使 Claude Code 暴露了更具体的品牌或品类 Skill，也只把本次附件和知识库内容作为证据，不切换运行方法。

只记录实际阶段耗时，不设置硬时限、自动超时或为了速度截断正文。

## 1. 先读材料，再问一个问题

读取已登记附件；没有附件时按任务只检索必要材料。先区分：

- 已知事实；
- 会改变事实安全、传播主线、信息权重、表达边界或交付可行性的未知项；
- 可以由当前智能体承担并在方向卡中显式展示的低影响假设。

每轮只问一个问题。普通任务最多两轮：

1. 第一轮只问影响最大的事实、时效、身份或发布场景缺口；没有这类缺口就直接进入方向确认。
2. 最后一轮必须展示本次写法选择，等待老师确认。

如果两轮后仍有事实或来源硬冲突，继续逐轮提问；额外轮次必须明确标记为 `hard_conflict`。受众、信息重心和语义温度尽量收进写法选项，不分别拆问。

生成任务不允许零轮访谈：即使材料已经充分，最后也要让老师确认真正采用的写法。老师在最初需求里已经明确主线时，把那句原话作为方向确认，不重复再问同一件事。

## 2. 动态形成写法选择

写法不是固定风格标签，而是会改变主张、读者关系或信息权重的编辑方案。每项最多包含：

```text
推荐｜<写法名称>
主张：<一句可被事实支持或推翻的主张>
适合：<受众／渠道／传播目的>
代价：<选择它会弱化什么>
```

默认只给推荐和一个真正不同的备选；只有第三条同样成立时才增加。每项保持短句，不展开论证。只有一条成立时，展示唯一推荐和“为什么没有备选”，仍须等待确认。只换标题、措辞或语气不算第二条方向。

🔴 CHECKPOINT · 成稿前必须得到老师对方向的明确选择或“按推荐写”。不要替老师补一句确认。

### 品类只规定任务边界

| 品类 | 必须完成 | 不能写成 |
|---|---|---|
| 新闻稿／官方通稿 | 交代新闻事实、意义与必要背景 | 媒体替品牌下结论，或把愿景写成既成事实 |
| 媒体观点供稿 | 给出可辩护的判断和证据链 | 品牌第一人称自述、宣传口号堆砌 |
| 媒体传播指引／核心信息 | 让媒体可直接取用，区分主张与支撑 | 一篇已经替所有媒体写死的成稿 |
| 演讲稿／串词 | 符合发言人身份、场合、听众和口语节奏 | 通稿改人称、无法说出口的书面语 |
| QA | 给出安全、直接、可追问的回答边界 | 只列关键词却无法照着回答 |
| 社会化文案／视频脚本 | 在平台限制内完成注意力和行动目标 | 把热闹当主线、遗漏品牌与事实边界 |

品类不规定固定段落顺序。结构、开篇和详略仍由本次方向与事实决定。

## 3. 先轻量保存方向

老师给了明确附件且没有触发扩展研究时，不在成稿前生成事实原子、材料表和完整决策 JSON。老师回答后第一步调用 `save --kind decision`，只把这一轮原话和选中方向保存到 `run.json`：

```json
{
  "interview": {
    "rounds": [
      {"n": 1, "kind": "gap|direction|hard_conflict", "question": "原话", "answer": "老师原话", "changed": "改变的判断"}
    ],
    "stopped_because": "为什么可以成稿"
  },
  "direction": {
    "options": [
      {"id": "A", "name": "写法名称", "claim": "主张", "suitable_for": "适合", "cost": "代价"}
    ],
    "selected": "A",
    "confirmed_by_user": true
  }
}
```

只记录选中的一项即可，不要把未选方向再次抄进 JSON。脚本仍拒绝没有方向确认、普通轮次超过两轮或一次多问。

只有附件不足、来源冲突、时效问题或知识库取证阻止成稿时，才读取 `references/research.md`，补充完整决策和最多 12 条事实原子。不要为“看起来更严谨”主动进入研究分支。

## 4. 一次成稿并立即交付唯一正文

依据已确认方向和本次证据边界直接写 `delivery.md`：

- 按主张推进，不按模板填空；
- 数字、日期、名称和比较范围照来源；
- 已明确舍弃的内容不进入正文；
- 不在写作时重新检索、换主线或补事实；
- 不输出写作说明、自我评价和技术记录。

如果成稿时发现主线或事实不成立，停止写作并回到对应问题；不要在正文里偷偷换方向。

正文写完立即运行：

```bash
$BLUEINK handoff --run "<run_id>"
```

`handoff` 会展示完整可修改稿件并记录真实耗时。不要等 `verify.json` 或 `delivery-check.md` 才让老师看到正文。稿件展示后，正文所有权已经交给老师：当前智能体不得再写、编辑或覆盖 `delivery.md`。

## 5. 交付后只复核高风险句

同一智能体收起前序策略理由，只对正文中这些句子做受限复核：

- 数字、日期、职务、车型和主体；
- `唯一、全部、普遍、均、最高` 等比较词；
- 同比、环比、超过、不足等数量关系；
- “因此、证明、说明、导致”等因果表达；
- 截至日期、当前状态和发布时点；
- 可能混入其他品牌或客户红线的表达。

这不是独立审查。对照来源检查这些句子，只记录确实发现的问题；没有问题就保持空数组。不得重写全文，也不得直接修改 `delivery.md`。每个问题只给原句、判断和局部替换建议，由老师决定是否采用。

调用 `save --kind verify`：

```json
{
  "issues": [
    {"quote": "能唯一定位正文句子的短片段", "judgement": "drifted|unsourced|stale", "risk": "问题类型", "source_quote": "可选的来源原句", "action": "建议替换为……"}
  ],
  "cross_brand": [],
  "redline_hits": [],
  "editorial_risks": []
}
```

附件快线不需要再次抄写 `sources_used`；脚本直接使用 `open` 已登记的附件。`quote` 不必手抄整句，只要能在脚本提取的高风险句中唯一定位即可。

脚本根据核验结果计算结论：

- `可进入人工初审`：没有 `drifted / unsourced / stale`，无跨品牌和红线；
- `有待确认项`：只有 `drifted` 或 `stale`；
- `暂不建议提交`：出现 `unsourced`、跨品牌或红线。

编辑红队不再默认单独运行。只有传播主线存在明显反方、敏感内容或高影响推断时，把最多三条问题写进 `editorial_risks`；弱问题不自动触发全文返工。

## 6. 生成独立核对卡并归档

执行 `close --run <run_id>`。脚本保持 `delivery.md` 不变，另生成 `delivery-check.md`，内容固定为：

```text
# 交付核对卡
<结论；只列未通过或待确认项>

## 实际来源
<只列本稿真正使用的来源>
```

`close` 的命令输出可能被折叠，不能代替最终回复。执行成功后，最终回复的第一个可见区块必须是
`delivery.md` 的完整内容，不得在正文前加“稿件已完成”、文件路径、撰写思路或质检报告。归档路径只能放在
全文之后作为附注。正文后只需给出核对结论与 `delivery-check.md` 路径，不得只给路径或摘要，也不得要求老师
另行打开文件才能看到稿件。可以直接复用 `close` 返回的正文。如果老师在核验后修改了 `delivery.md`，脚本会
拒绝生成核对卡；保留老师版本，只说明核验对应的版本已经变化。

## 失败处理

| 触发条件 | 处理 | 仍失败 |
|---|---|---|
| `save decision` 拒绝 | 按报错只修轻量方向字段；不抽取事实原子 | 正文仍按已确认方向生成，记录问题放到交付后处理 |
| 事实来源越界或不存在 | 回到附件／研究边界，不静默换来源 | 向老师问一个阻塞问题 |
| `handoff` 后发现事实问题 | 不改 `delivery.md`，只在 `issues` 给局部建议 | 由老师决定是否采用 |
| `save verify` 判有待确认 | 保留老师正文并展示具体待确认句 | 不冒充可提交终稿 |
| `close` 发现正文版本变化 | 保留老师版本，说明旧核验已失效 | 不生成核对卡，不重跑整条写作链，不覆盖正文 |
