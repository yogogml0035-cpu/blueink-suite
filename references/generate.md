# 默认生成快线

这份文件是生成任务唯一默认加载的运行指导。目标是用一次访谈收敛和一次高风险复核完成交付；不要把它重新拆成多个角色或阶段文档。

## 1. 先读材料，再问一个问题

读取已登记附件；没有附件时按任务只检索必要材料。先区分：

- 已知事实；
- 会改变事实安全、传播主线、信息权重、表达边界或交付可行性的未知项；
- 可以由当前智能体承担并在方向卡中显式展示的低影响假设。

每轮只问一个问题。普通任务最多两轮：

1. 第一轮只问影响最大的事实、时效、身份或发布场景缺口；没有这类缺口就直接进入方向确认。
2. 最后一轮必须展示本次写法选择，等待老师确认。

如果两轮后仍有事实或来源硬冲突，继续逐轮提问；额外轮次必须明确标记为 `hard_conflict`。受众、信息重心和语义温度尽量收进写法选项，不分别拆问。

## 2. 动态形成写法选择

写法不是固定风格标签，而是会改变主张、读者关系或信息权重的编辑方案。每项最多包含：

```text
推荐｜<写法名称>
主张：<一句可被事实支持或推翻的主张>
适合：<受众／渠道／传播目的>
代价：<选择它会弱化什么>
```

有两到三条真实方向时给出推荐和备选。只有一条成立时，展示唯一推荐和“为什么没有备选”，仍须等待确认。只换标题、措辞或语气不算第二条方向。

🔴 CHECKPOINT · 成稿前必须得到老师对方向的明确选择或“按推荐写”。不要替老师补一句确认。

### 品类只规定任务边界

| 品类 | 必须完成 | 不能写成 |
|---|---|---|
| 新闻稿／官方通稿 | 交代新闻事实、意义与必要背景 | 媒体替品牌下结论，或把愿景写成既成事实 |
| 媒体观点供稿 | 给出可辩护的判断和证据链 | 品牌第一人称自述、宣传口号堆砌 |
| 媒体传播指引／核心信息 | 让媒体可直接取用，区分主张与支撑 | 一篇已经替所有媒体写死的成稿 |
| 演讲稿／串词 | 符合发言人身份、场合、听众和口语节奏 | 通稿改人称、无法说出口的书面语 |
| QA | 给出安全、直接、可追问的回答边界 | 只列关键词却无法照着回答 |
| 社会化文案／视频脚本 | 在平台限制内完成注意力和行动目标 | 把热闹当主线、遗漏品牌与事实边界 |

品类不规定固定段落顺序。结构、开篇和详略仍由本次方向与事实决定。

## 3. 建立最小事实原子

方向确认后，只保留正文会用的事实，最多 12 条。每条必须有：

```json
{
  "id": "F1",
  "statement": "准确、有限定条件的事实",
  "source_path": "登记附件绝对路径或绑定根内路径",
  "source_quote": "足以复核的来源原句",
  "source_date": "来源日期或时间范围",
  "scope": "比较对象、时间和口径范围",
  "allowed_strong_words": []
}
```

`allowed_strong_words` 只允许 `唯一、全部、普遍、均、最高`。来源没有明确覆盖比较范围时保持空数组。不要把推断、传播建议或标题写进事实原子。

如果需要观点鲜明，把事实和分析分开：事实句保持边界；观点句写成“这意味着、可以理解为、更像是”等可被讨论的判断，不把分析伪装成来源结论。

## 4. 保存 run.json

调用 `save --kind decision`，输入结构：

```json
{
  "interview": {
    "rounds": [
      {"n": 1, "kind": "gap|direction|hard_conflict", "question": "原话", "answer": "老师原话", "changed": "改变的判断"}
    ],
    "stopped_because": "为什么可以成稿"
  },
  "direction": {
    "options": [
      {"id": "A", "name": "写法名称", "claim": "主张", "suitable_for": "适合", "cost": "代价"}
    ],
    "selected": "A",
    "confirmed_by_user": true
  },
  "facts": [],
  "decision": {
    "communication_task": "传播任务",
    "category": "交付品类",
    "audience": "受众",
    "publisher": "谁在说",
    "material_plan": {"foreground": [], "background": [], "discarded": []},
    "information_budget": "各部分笔墨分配",
    "expression_bounds": [],
    "assumptions": []
  }
}
```

脚本拒绝：没有方向确认、普通轮次超过两轮、一次多问、事实超过 12 条、来源越界、强比较词未在允许集合中。

## 5. 一次成稿

只依据 `run.json` 的已确认方向、事实原子和决策写 `draft.md`：

- 按主张推进，不按模板填空；
- 数字、日期、名称和范围照事实原子；
- `discarded` 内容不进入正文；
- 不在写作时重新检索、换主线或补事实；
- 不输出写作说明、自我评价和技术记录。

如果成稿时发现主线或事实不成立，停止写作并回到对应问题；不要在正文里偷偷换方向。

## 6. 只复核高风险句

同一智能体收起前序策略理由，只对正文中这些句子做受限复核：

- 数字、日期、职务、车型和主体；
- `唯一、全部、普遍、均、最高` 等比较词；
- 同比、环比、超过、不足等数量关系；
- “因此、证明、说明、导致”等因果表达；
- 截至日期、当前状态和发布时点；
- 可能混入其他品牌或客户红线的表达。

这不是独立审查。只输出问题句与来源对应，不重写全文。发现问题时最多做一次局部修正，再只复核被改句子。

调用 `save --kind verify`：

```json
{
  "claims": [
    {"quote": "正文原句", "risk": "比较范围", "fact_ids": ["F1"], "judgement": "matched|drifted|unsourced|stale", "source_quote": "来源原句", "action": "无需处理或局部建议"}
  ],
  "cross_brand": [],
  "redline_hits": [],
  "editorial_risks": [],
  "sources_used": [
    {"path_or_url": "绝对路径或官方 URL", "kind": "需求材料", "date": "日期"}
  ]
}
```

脚本根据核验结果计算结论：

- `可进入人工初审`：没有 `drifted / unsourced / stale`，无跨品牌和红线；
- `有待确认项`：只有 `drifted` 或 `stale`；
- `暂不建议提交`：出现 `unsourced`、跨品牌或红线。

编辑红队不再默认单独运行。只有传播主线存在明显反方、敏感内容或高影响推断时，把最多三条问题写进 `editorial_risks`；弱问题不自动触发全文返工。

## 7. 交付

执行 `close --run <run_id>`。脚本生成 `delivery.md`，内容固定为：

```text
<正文>

交付前核对卡
<结论；只列未通过或待确认项>

实际来源
<只列本稿真正使用的来源>
```

业务回复直接使用 `delivery.md`，不再重新组织或改写正文。

## 失败处理

| 触发条件 | 处理 | 仍失败 |
|---|---|---|
| `save decision` 拒绝 | 按报错只修输入字段，不改正文 | 停在方向确认后，报告具体字段 |
| 事实来源越界或不存在 | 回到附件／研究边界，不静默换来源 | 向老师问一个阻塞问题 |
| `save verify` 判有待确认 | 保留正文并展示具体待确认句 | 不冒充可提交终稿 |
| `close` 无法生成交付 | 先保留已核验正文，报告后台错误 | 不重跑整条写作链 |
