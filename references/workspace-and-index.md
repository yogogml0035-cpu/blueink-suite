# 工作空间与索引

首次绑定时读这里。本次品牌与知识库不匹配时读这里。需要理解索引字段、检索切片或官方来源白名单时读这里。

下文用 `$BLUEINK` 代指当前电脑上已经解析并试跑过的 `blueink.py --project <当前项目根>` 命令，不是可跨平台原样复制的 shell 变量。macOS 通常使用 `python3`；Windows 通常优先 `py -3`，找不到再试 `python`。

## 一 · 首次运行：先确定证据从哪来

三种情形，按这个顺序判断。**判断错了后面全错**，因为它决定所有检索的边界。

### 情形一 · 老师给了明确的参考文件路径

那就是本次的证据，不需要品牌知识库，也不需要绑定：

```bash
$BLUEINK open --mode 生成 --brand "<本次品牌>" --attach "<文件绝对路径>" [--attach …]
```

**有附件时不要先跑 `status`、`bind`、`check-brand` 或 `index`。** 附件已经决定本次证据边界，直接 `open`；只有没有附件时才进入下面的工作空间判断。

未绑定的项目也能这样开始。**"参考这两个文件写一篇"是完全正常的请求**，为它索要一次绑定就是把五分钟的任务变成一次知识工程。运行记录会把 `bound` 记为 `false`、把 `evidence_boundary` 记为 `attachments`。

缺到无法成稿时向老师要，**不要自己去找**：没有绑定根，就没有"可以自主检索的范围"，任何目录都是越界。审计只认登记过的附件。

### 情形二 · 项目还没有绑定知识库

先确认，再在访谈里问，一次问一件：

```bash
$BLUEINK status          # 正常返回；读取 bound 判断是否绑定
```

要问出来的只有三件事，问一次，之后不再问：

1. 当前负责的品牌是什么；
2. 该品牌知识库目录在哪；
3. 哪些官方公开来源可用（联网取证前才需要；不急着问）。

第 3 项之外都是必需的。语料布局（初终稿、需求素材、反馈分别在哪）**不要问**——索引会自动判断，问了反而是在替它做本该自动完成的工作。

```bash
$BLUEINK bind --brand "<品牌>" --kb "<知识库目录绝对路径>" \
              [--official "<官网>"]
$BLUEINK index
```

### 老师说"还没有知识库目录"

**不要卡在这里，也不要让他先去建目录再回来。** 加 `--create`：

```bash
$BLUEINK bind --brand "<品牌>" --kb "<你和他商定的目录路径>" --create
```

它会建出标准语料布局并写好配置：

```
<知识库目录>/
├── README.md          这个目录放什么、不需要做什么
├── 01-原文资产/       官方资料、品牌基础、产品资料
├── 02-需求素材/       客户需求、brief、原始素材
├── 03-初终稿对比/     同一篇的初稿与终稿
├── 04-经验总结/       对接经验、传播红线、改稿规律
└── 05-成品参考/       已采用的终稿，按品类放
```

然后告诉老师：把这个品牌的稿件丢进去，跑一次 `index` 就能用。**明确告诉他三件不需要做的事**——不需要先分好类（分不清就随便放，索引会给候选标签）、不需要改文件名（文件名里的日期和品类字样是识别线索，改名反而丢掉它们）、不需要清理旧文件（证据带时效，取证时按日期取近的）。

**只有一件事必须做：这个目录里只放这一个品牌的材料。** 跨品牌隔离靠"检索根只有一个"实现，放进别家客户的文件，隔离就失效了。

刚建出来的目录是空的，检索会返回空——这一点 `bind` 会明确提示，不要让老师以为已经可以直接写稿了。

### 情形三 · 已绑定，但本次要写的品牌可能不是绑定的那个

访谈里确认品牌之后核对一次：

```bash
$BLUEINK check-brand --brand "<本次品牌>"
```

判定认简称：绑定「理想汽车」时说「理想」算匹配。但「现代中国」与「现代汽车」互不为子串，判为不匹配——那正是需要拦的一类，因为「现代汽车」下面是两个同级品牌。

**不匹配时不要自己选边，也不要继续。** 用当前知识库给另一个品牌写稿，会把别家客户的表达和事实带进这一稿，而这类错误在成稿里看不出来——它不会报错，只会让稿子在某几句话上变成另一个客户的口吻。把三条出路交给老师选：

| 出路 | 什么时候选 | 怎么做 |
|---|---|---|
| 品牌名写错了 | 这一稿其实就是绑定的那个品牌 | 改过来重开 |
| 换项目 | 确实要写另一个品牌 | 到那个品牌的项目目录去执行；没有就新建一个目录再 `bind`（可加 `--create`） |
| 本次不用知识库 | 只想参考几份指定文件 | 在一个未绑定的目录里 `open --attach` |

**改绑不是第四条出路。** `--force` 不能改品牌；换品牌必须新建项目目录。它只在两类情况使用：确认一个被结构启发式误判的单品牌目录，或当前品牌换电脑／移动知识库路径。迁移路径会清空可重建索引并要求立刻重跑 `index`，学习记忆与历史运行保留。

`open --brand` 会在开启运行时再挡一次，所以**品牌名一律传给它**。被拒绝的运行不会落盘，不会留下一条"品牌不对但看起来正常"的记录。

## 二 · 目录布局

```
当前项目/
└── .blueink/
    ├── workspace.yaml      品牌、知识库路径、官方来源、语料布局
    ├── index/
    │   ├── index.json      旁路增量索引
    │   └── cache/          官方页面片段缓存（按任务，不长期保留）
    ├── learning/
    │   ├── memory.json                 当前品牌的条件化记忆
    │   └── methodology-candidates.json 方法论候选（只记录，不自动生效）
    └── runs/
        ├── index.json      历次运行摘要
        └── <run_id>/       单次运行的完整调用轨迹
```

三条纪律：

- **绑定后的索引与写作流程只读源知识库。** 唯一写入例外是老师显式要求的 `bind --create`：它只创建空目录骨架与说明文件，后续不改写、重命名或移动语料。
- **`.blueink/index/` 可删可重建，`.blueink/learning/` 不可自动重建。** `runs/` 受留存策略清理；删除整个 `.blueink/` 会丢失绑定、记忆和运行记录。新建工作空间会写入 `.blueink/.gitignore`，默认不随项目仓库复制；迁移记忆应单独备份 `learning/`。
- **一个工作空间只绑定一个品牌知识库。** 要换品牌就换项目；跨品牌隔离不靠提示词。

## 三 · 本次附件的登记

老师本次显式提供的文件是本次任务的证据，**不受绑定根限制**——绑定根约束的是系统自己去找什么，不是老师授权它读什么。但它必须登记，登记发生在开启运行的那一次：

```text
<当前平台 Python 3.9+ 命令> "<当前插件根>/scripts/blueink.py" \
  --project "<当前项目根>" open --mode 生成 \
  --attach "<当前电脑附件绝对路径>/【指引】xxx.md" \
  --attach "<当前电脑附件绝对路径>/【新闻稿】xxx.md"
```

写进 `meta.json` 的 `task_attachments`：每条含 `path`（解析后的绝对路径）、`sha256`、`bytes`、`brand`、`source: user`。同时写 `evidence_boundary`：**有附件时默认 `attachments`**，没有附件时是 `kb`。要显式覆盖用 `--evidence-boundary kb|attachments`。

三件事说清楚：

- **登记是登记，不是审批。** 它不阻止任何路径，只让"老师给的"与"自己越界读的"在证据上可区分。没有它，审计 A2 只能二选一：要么放过真正的跨品牌越界，要么把老师的授权判成违约。
- **必须在同一次 `open` 里登记。** `task_attachments` 是本次证据边界的输入；事后补登记只能重开一次运行，前一次就成了废记录。附件路径给绝对路径，且必须是文件不是目录，不存在时 `open` 直接拒绝。
- **记内容哈希**是因为附件多半在知识库之外，事后可能被改动或移走。哈希让"当时读到的是哪一版"仍然可查。

`evidence_boundary` 是**声明**，不是锁。`attachments` 的含义是"先只用附件成稿"；真出现会阻止成稿的高影响缺口时照样可以检索，只要把缺口写进证据回执的 `gaps`。声明的作用是让审计能发现"没有缺口却展开了整库普查"这种静默浪费——那时 A2 会带一条可见提示，但不判违约。

## 四 · workspace.yaml

带注释的完整模板在 `assets/workspace.template.yaml`，可直接复制。

```yaml
version: 3
brand: 理想汽车
brand_key: lixiang
kb_root: <当前电脑上的理想汽车知识库绝对路径>
bound_at: 2026-08-22
official_sources:
  - name: lixiang.com
    url: https://lixiang.com
corpus_layout:
  原文资产: 01-原文资产
  需求素材: 02-需求素材
  初终稿对比: 03-初终稿对比
  经验总结: 04-经验总结
  成品参考: 05-成品参考
notes: ""
```

- **`brand` 是写进稿子要认的品牌名，`brand_key` 是文件名和索引里用的短标识。** 前者用于跨品牌污染检查，后者用于路径与命名。
- **`corpus_layout` 可以为空。** 空的时候索引按文件名和路径关键词自动判断证据类型。填了就优先按它判断，准确度更高。
- **`official_sources` 是白名单，不是搜索建议。** 写入时统一归一化成主机名（见第六节）。
- `notes` 用来记这个工作空间的特殊约定，比如"绑定到现代 N 品牌，不是现代中国"。

```bash
$BLUEINK bind --brand "理想汽车" --kb "<目录>" \
        [--brand-key lixiang] [--official lixiang.com] [--notes "特殊约定"] [--force]
$BLUEINK status
```

`bind` 会拒绝这些情况：

| 拒绝 | 为什么不只是告警 |
|---|---|
| 目录不存在 | 检索会永远返回空 |
| 目录里一份可读文本都没有 | 同上 |
| **绑到了品牌集合层** | 见下 |
| **品牌改变** | 即使带 `--force` 也拒绝；换品牌必须新建项目 |
| **知识库路径改变但未确认** | 换电脑或移动目录后需加 `--force`；随后旧索引会被清空并要求重建 |

**品牌集合层是拦截，不是告警。** 判定方式是结构启发式：子目录里没有任何语料布局特征词（原文／初终／经验／成品／需求／反馈……）、而是并列的若干名字，就判为集合层。这条规则同时拦住两种情况：

- 绑到四品牌总根（子目录是 东风奕派、千里科技、现代汽车、理想汽车）；
- **绑到"现代汽车"这一层**——它下面是 现代中国 与 现代 N 品牌 两个同级品牌，绑在这一层等于同时打开两套调性，会写出混用两种品牌表达的稿子。

告警会被忽略，而它的后果是整套稿子跑偏。确认某个目录确实是单一品牌时用 `--force`，此时会明确提示"跨品牌污染检查会因此失效"。

## 五 · 旁路索引：不要求老师先整理知识库

**索引不追求一次分类正确。** 这是它能落地的前提——"知识库维护困境"来自一个错误目标：先把知识库整理对，再让 AI 用。实际上没人有时间做这件事。

所以索引的设计是：

- 只读扫描源库，保留原始目录和文件不变。
- 低置信度文件**同时保留多个候选标签**，不强行归类。
- **只有某个模糊项会实际影响当前这一稿时**，主智能体才在访谈中问。
- 文件新增或修改时按内容哈希增量更新，不重新处理整个库。

```bash
$BLUEINK index            # 首次全量／之后按哈希增量
$BLUEINK index --full      # 忽略现有索引，全量重建
$BLUEINK index --limit 20   # 试跑预览，只扫前 20 个文件且不落盘
```

`--limit` 是**预览**，不写索引。这一点必须记住：它如果落盘，一次 `--limit 5` 就会把 186 条索引截成 5 条，而输出里的"移除 181"会让人以为知识库真的少了文件。

每条索引记录：

```json
{
  "path": "03-初终稿对比/i8上市稿-初稿vs终稿.md",
  "hash": "3f9a…",
  "size": 18422,
  "mtime": "2026-06-12T09:14:03",
  "ext": "md",
  "evidence_type": ["初终稿对比"],
  "stage": "对照",
  "categories": ["新闻稿"],
  "candidates": ["新闻稿", "媒体观点供稿"],
  "confidence": 0.55,
  "date": "2026-06-11",
  "title": "i8 上市稿 初稿 vs 终稿",
  "summary": "开头 200 字",
  "extractable": true,
  "content_status": "text",
  "instruction_artifact": false,
  "entities": ["i8", "增程平台"]
}
```

- `evidence_type` 取 `原文资产` / `初终稿对比` / `经验总结` / `成品参考` / `需求素材` / `反馈` / `历史技能产物` / `未分类`。
- `stage` 取 `初稿` / `终稿` / `对照` / `未知`。**风格轨只用 `终稿`，编辑策略轨只用 `对照` 和 `经验总结`。**
- `confidence` 低于 0.5 时 `candidates` 保留多个标签，检索时按较低权重返回。
- `content_status` 是**诚实标记**，取值见下表。
- `instruction_artifact` 见第五节。

| `content_status` | 含义 | 能不能当"已检索" |
|---|---|---|
| `text` | 正文已读入（Markdown、纯文本、JSON/YAML、CSV/TSV、HTML，以及**解包取正文的 DOCX / PPTX**） | 能 |
| `metadata_only` | PDF、早期 DOC/XLS/PPT 格式、图片：只登记路径与元数据 | **不能** |
| `metadata_only_large` | 超过 10MB，没读正文 | **不能** |
| `metadata_only_unreadable` | 编码坏、压缩包畸形或解析失败 | **不能** |
| `unsupported` | 未识别的扩展名 | **不能** |

**DOCX 与 PPTX 会真的读正文。** 这两种格式就是带 XML 的 zip，标准库能解包——源库里大量交付物是 docx（`【整理前】` 全库有一百多份），放弃它们等于放弃一批真实语料。解压总量与成员数都设了上限，畸形压缩包会降级成 `metadata_only_unreadable` 而不是拖死索引。

**只有元数据的文件，正文没被读过。** 不要把它当成"这份资料已经检索过了"——要么让老师在访谈里说明内容，要么标成缺口，要么先转成文本再入库。

**增量按内容哈希，不按修改时间。** 同步工具刷新过 mtime 但内容没变的文件不会重复入索引；反过来，内容变了而 mtime 没变的文件也照样能被发现。

**跳过项会被报出来。** 符号链接一律不跟随（一条指向别的品牌目录的链接就足以让"检索根只有一个"失效），不可读目录也记下来。`index` 的输出和 `doctor` 都会列出跳过了什么——静默跳过会让人以为那批资料已经进过索引。

## 六 · 历史技能包不当证据

知识库里躺着混进来的写作技能包是常态（`04-经验总结原稿/lixiang-pr-writer/` 就是一个）。里面是提示词和固定模板，**正是"结构固化：强制开篇铺垫行业背景"这条反馈的来源文件**。把它们当经验证据检索出来，等于让外部提示词反向控制本次流程。

判定按**目录**而不是按文件名：目录里出现 `SKILL.md` / `AGENTS.md` / `CLAUDE.md`，则该目录整棵子树都标成 `instruction_artifact`。

**只按文件名过滤是不够的**——技能包里的固定模板不写在 `SKILL.md` 里，写在它旁边的 `04-经验总结原稿/xxx-writer/references/press_release_templates.md` 里。只拦入口文件，模板照样会在"新闻稿 结构"这类检索里排到前列。

这些文件仍然被索引（要能查到它们存在、在哪、有多少），只是：

- `evidence_type` 记为 `历史技能产物`，品类标签清空（否则一份带六个品类标签的旧 `SKILL.md` 会在任何品类检索里高分命中）；
- 默认不出现在 `retrieve` 结果里，返回值里会报 `excluded_instruction_artifacts` 计数；
- 只有明确要审计这些技能包时才用 `--include-instruction-artifacts` 取回。

## 七 · 检索：返回切片清单，不返回全文

```bash
$BLUEINK retrieve --run <run_id> \
        --query "交付 产能 平台" [--category "媒体观点供稿"] \
        [--track fact|style|strategy] [--limit 12] [--since 2026-01-01] \
        [--include-instruction-artifacts]
```

输出候选文件的路径、证据类型、stage、时间、摘要、`content_status` 和命中理由。**由子智能体自己决定读哪几份**，检索不替它读。

`--track` 按三轨判据分别排序：

| track | 优先返回 | 排除 |
|---|---|---|
| `fact` | 原文资产、需求素材、时间近的 | 无（但初稿降权） |
| `style` | 终稿、成品参考、同场景、时间近的 | 初稿、对照文件 |
| `strategy` | 初终稿对比、经验总结、反馈 | 单纯的终稿 |

**不加 `--track` 时三轨混排，容易把初稿当风格样本，不推荐。**

`--loose` 让品类不命中的候选也保留（降权而不是丢弃）。指定了 `--category` 却几乎没有命中时用它——多半说明这个交付物在库里没有同品类先例，那正是需要放宽的场合。

检索永远限制在 `kb_root` 之内。这不是一条需要反复申明的规则，而是 `retrieve` 的实现方式：它只从索引里查，而索引只包含 `kb_root` 下的文件。

## 八 · 官方来源：白名单是一道机械闸

日常任务先检索本地。只在四种情况查官方渠道：本次任务有明显时效性；本地事实缺失或存在版本冲突；老师明确要求补最新信息；素材里出现尚未进入本地库的新产品、人物或活动。

**每次联网前必须过这道闸，退出码非 0 就不访问：**

```bash
$BLUEINK official check-url --url "https://www.lixiang.com/news/xxx"
$BLUEINK official list
$BLUEINK official add --url "ir.lixiang.com"
```

判定规则只有一条：**主机名等于白名单域名，或者是它的子域。** 实现只有一处（`scripts/official.py`），审计、检索和 Agent 契约都调用它，不各写一份。

写入白名单时会归一化：接受完整 URL（老师会直接粘新闻中心链接），路径被丢掉并告知；`www.` 前缀归一化到主域，否则 `https://lixiang.com/...` 会被自己的白名单拦住，而症状是"官网也被拒了"，下一步老师就会绕过白名单。

拒绝这几类伪装，它们肉眼都像官网：

| 输入 | 结果 |
|---|---|
| `https://lixiang.com.evil.cn/a` | 拒绝 · 后缀伪装（用字符串包含判断会放过它） |
| `https://lixiang.com@evil.cn/` | 拒绝 · 用户名伪装 |
| `https://evil.cn/https://lixiang.com` | 拒绝 · 路径伪装 |
| `http://127.0.0.1/lixiang.com` | 拒绝 · IP 直连 |
| `*.lixiang.com` 写进白名单 | 拒绝 · 通配白名单等于没有白名单 |
| `file://`、`javascript:` | 拒绝 · 只允许 http/https |
| `https://ir.lixiang.com/x`、`https://LIXIANG.COM/News` | 允许 · 子域与大小写 |

**搜索结果自称官网不能跳过这一步。** 媒体转述里的数字经常是记者换算过的，不能当事实来源。

- 官方资料只用于事实与时间线，不用来推断客户内部偏好。官网上没写"我们喜欢什么风格"。
- 每次获取记录 URL、获取时间、页面日期，片段缓存在 `index/cache/`，同一任务不重复抓取。
- 无法访问或无法确认是官方来源时，标成缺口，不用普通媒体内容静默替代。

## 九 · doctor：一条命令看清当前状态

`doctor` 也会打印上次运行的**证据边界与已登记附件**。这是"老师给的文件到底被当成本次证据了吗"这个问题的唯一答案，而它只存在 `meta.json` 里——放进 `doctor` 是因为那才是老师会去看的那一条命令。声明了 `attachments` 却一份都没登记时会给告警：那说明 `open` 时漏了 `--attach`。

```bash
$BLUEINK doctor
```

它检查并报告：**当前解析到的项目根是哪个目录**；是否已绑定；官方白名单是否为空；`kb_root` 是否仍然存在且可读；索引是否新鲜（有多少文件变更未入索引、跳过了什么）；记忆库有多少条、多少条待确认；上次运行是哪个 `run_id`、走到了哪一步、有没有未闭合的运行。

第一项最容易被忽略却最要紧。绑定会在项目目录内向上查找 `.blueink/`，但**不会让下级项目继承家目录的 `.blueink/`，也拒绝直接把家目录绑定成项目根**。`status` 与 `doctor` 的第一行都会打印最终解析到的项目根；看到不对先修正 `--project`，不要继续检索。

`retrieve` 会先确认知识库仍存在，并核对索引里的品牌与根路径都属于当前工作空间；任何一项不一致都拒绝返回旧候选并要求 `index --full`。**"检索返回空"最常见的原因才是尚未建立索引或确实没有命中。** 先跑 `doctor`，不要先怀疑索引质量。
