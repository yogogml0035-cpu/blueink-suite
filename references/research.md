# 条件证据研究

只有默认快线出现高影响缺口、来源冲突、时效问题，或任务明确需要知识库／官方补充时读取。目标是闭合已经命名的缺口，不做知识库普查。

## 边界

1. 老师登记附件优先，事实扩展不改变其授权地位。
2. 自主检索只能在绑定 `kb_root` 内；联网只访问已登记官方来源。
3. 事实、风格和编辑判断分开：官方资料只补事实，近期终稿只提供表达参考，初终稿差异和明确反馈才支持编辑候选。
4. 找到足以回答缺口的证据立即停止。

## 最小流程

1. 在 `run.json.decision.needs_evidence` 指名缺什么、为什么会改变稿件。
2. 知识库检索使用 `retrieve --track fact|style|strategy`；官方 URL 先用 `official check-url`。
3. 初稿尚未 `handoff` 时，把使用的来源、完整编辑决策和最多 12 条事实原子通过 `save --kind decision` 更新进同一份 `run.json`。
4. 来源冲突不静默选边：逐轮只问一个冲突，老师裁决后记录原话和改变的判断。

如果高影响缺口在 `handoff` 后才暴露，不再改写 `draft.md`，只把问题和局部替换建议写入轻量核验 `issues`，交给老师处理。

## 时效

来源中的“截至某日、当前、最新、上市两周、已完成比例”等表达如果与实际发布时点不一致，先问发布时点或补充最新来源。不能因为财报已经发布，就假设稿件仍按财报发布日投放。

## 失败处理

| 触发条件 | 处理 | 仍失败 |
|---|---|---|
| 知识库未绑定或路径失效 | 读取 `troubleshooting.md` 修复工作空间 | 向老师要附件或有效根路径 |
| 官方地址不在白名单 | 停止访问，展示 URL | 由老师确认是否加入 |
| 两个来源硬冲突 | 记录来源、日期和冲突原句，只问一个裁决问题 | 保持 blocked，不成稿 |
| 文件不可读或只有元数据 | 标成缺口，不声称已经取证 | 要求可读文本或转换后的附件 |
