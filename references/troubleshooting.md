# 问题定位手册

稿子不对的时候读这里。目标是**在两分钟内定位到具体角色和具体文件**，而不是整包重读。

最痛的一类问题是这个：出现问题了不知道问题出在哪个技能的哪个 md。这套系统把定位变成三步。

## 第一步 · 看现象，落到角色

| 现象 | 首要责任 | 先看哪个文件 | 看什么 |
|---|---|---|---|
| 事实错了 | 证据研究员 | `evidence.json` | 这条事实的 `source` 和 `source_date` |
| 关键资料漏了 | 证据研究员 | `evidence.json` | `discarded` 里是不是被误舍，`gaps` 里是不是标了但没人管 |
| 来源不可靠 | 证据研究员 | `evidence.json` | 是否用了非白名单来源；`confidence: low` 的事实进了正文 |
| 主线不对 | 编辑策略师 | `strategy.json` | `recommended_line.why` 站不站得住 |
| 结构僵、像模板 | 编辑策略师 | `strategy.json` | `applicable_conventions` 里是不是把参考稿当纪律了 |
| 信息权重失衡 | 编辑策略师 | `strategy.json` | `information_budget` 与 `material_plan.foreground` 的权重 |
| 表达差 | 专业写作者 | `draft.md` + `program.json` | 程序说的和正文写的是不是一件事 |
| 执行偏离了确认方案 | 专业写作者 | `write-receipt.json` | `deviations` 有没有申报 |
| 杜撰没被发现 | 来源核验员 | `verify.json` | `coverage.unsourced` 是不是漏判 |
| 跨品牌信息没拦住 | 来源核验员 | `verify.json` | `cross_brand` 是否为空但正文里确有 |
| 方向明显不对却没人反对 | 编辑反方 | `adversary.json` | `attacks` 是不是全是轻微项，`missed_stronger_line` 是不是漏了 |
| 老师的反馈没生效 | 反馈归因员 / 记忆 | `feedback.json`、`learning/memory.json` | 归成了哪一级、置信度够不够、是否还在 `pending_confirmation` |
| **完全没有这些文件** | 没有创建运行记录 | `.blueink/runs/` | 是否用 `open` 创建了本次 `run_id` |

最后一行说明当前没有可审计的 BlueInk 运行。先确认本次是否通过显式入口创建了 `run_id`，不要把无运行记录的输出当成已审计结果。

## 第二步 · 读回执，判断是"判断错了"还是"没执行"

两种失败要分开，处置完全不同：

- **判断错了**：回执里写着一个理由，但这个理由不成立。→ 退回该角色所在阶段重做，并把这次错误的判断作为反馈证据。
- **没执行**：回执里根本没有这一项，或者写了但正文没照做。→ 不是判断问题，是契约违约。看 `write-receipt.json` 的 `deviations` 有没有申报；没申报的偏离要作为编排问题记下来。

一个具体例子。老师说"这段技术罗列跟主线没关系"：

1. 查 `strategy.json` 的 `material_plan`。这段素材在 `foreground` 里 → 策略判断错了，退回第 3 步。
2. 在 `discarded` 里却出现在正文 → 写作者重新选了素材，查 `write-receipt.json` 的 `deviations`；没申报就是违约。
3. 两处都没有这条素材 → 写作者自行补了内容，查 `missing_facts` 是否为空——为空说明它没有申报就自己加了。

**同一个现象，三种根因，三个不同的处置。** 没有回执时这三者无法区分，那就是无法定位的根源。

## 第三步 · 跑审计器

审计器把五项验收契约变成机械检查，直接告诉你这次运行在哪一条上违约。

```bash
$BLUEINK audit --input "<当前项目根>/.blueink/runs/<run_id>" --output "<当前电脑临时目录>/verdict.json"
$BLUEINK audit --run <run_id>
```

它检查五项：

| 契约 | 检查内容 | 判为违约的情况 |
|---|---|---|
| `A1 入口唯一` | `meta.json` 记录了 Claude Code 显式启动与 `run_id` | 缺 `meta.json`；`started_via` 不是 `/blueink-suite` 或规范化的 `/blueink-suite:blueink-suite`；缺 `run_id` |
| `A2 单品牌隔离` | 所有 `read_paths` 落在 `kb_root` 内**或已登记的本次附件**内，且文件真实存在；无跨品牌实体 | 出现既不在 `kb_root`、也不在 `meta.task_attachments` 里的路径；相对路径含 `..`；**声称读过但文件不存在（等于凭空写出的引用）**；软链接指向库外；`verify.cross_brand` 非空 |
| `A3 动态访谈` | 每轮恰好一个问题；有停止理由 | 某轮 `question` 含多个问号；缺 `stopped_because`；连续两轮 `changed` 为空 |
| `A4 责任隔离` | 六份回执的 `role` 与阶段对应；写作者未扫库；核验角色未改稿 | 写作者 `read_paths` 含未授权的库内文件；写作回执缺 `deviations` 字段；有正文却没有写作回执；`verify.json` / `adversary.json` 出现改写后的句子 |
| `A5 输出有效` | 无 `unsourced`；来源清单是**真的被打开过的**文件的子集；核对卡结论口径正确 | `coverage.unsourced > 0`；`sources_used` 出现只在检索候选里出现过、没被任何角色打开的文件；结论行与 `verdict` 不一致；`delivery.md` 泄漏技术轨迹 |

输出：

```json
{
  "run_id": "...",
  "verdict": "pass | violated | incomplete",
  "checks": [
    {"id": "A2", "name": "单品牌隔离", "status": "pass|fail|skip",
     "detail": "...", "evidence": ["文件:字段"]}
  ],
  "failed": ["A5"],
  "missing_artifacts": ["adversary.json"]
}
```

三种结论：

- `pass`：五项全部通过。**不代表稿子好**，只代表流程没有违约。质量判断仍然是老师的。
- `violated`：至少一项 fail。看 `failed` 和对应 `detail`。
- `incomplete`：运行没跑完，有回执缺失。`missing_artifacts` 列出缺哪些。**运行中途中断很常见，不要把 incomplete 当成 bug。**

**`pass` 能证明什么、不能证明什么，要分清：**

| 契约 | 它真的能证明 | 它证不了 |
|---|---|---|
| A1 | 这次走了技能，有 run_id | — |
| A2 | 读过的路径都在绑定库内且文件真实存在 | 正文里的品牌污染（那要靠核验员的人为判断） |
| A3 | 形式上每轮一问、有停止理由；零轮时理由非空 | **问题问得对不对**——一个照本宣科的三问也能通过；一次问多个而**不用问号**也抓不到 |
| A4 | 各角色回执齐、写作者没越权读文件（路径两侧都归一化后比对） | 各角色是不是真的在独立判断；核验／反方改稿只按**字段名**启发式识别，换个字段名写改写内容抓不到 |
| A5 | 无无来源事实、结论口径自洽、来源清单里每一项都真的被打开过（**检索候选不算读过**） | 事实本身对不对（来源可能就是错的） |

换句话说，审计器守的是**形式契约**，它让静默失败变成可见失败。判断内容对不对，仍然只有文案老师能做——这是设计选择，不是待补的缺口。声称机器能判断文案质量，等于把最难的那件事又推回给老师，还额外骗了他一次。

**每次运行结束都跑一次 audit。** 它比人眼更早发现"写作者其实重新扫了库""访谈其实是问卷""来源其实没覆盖"这三类静默失败。

## 本地环境的反直觉事实

这些是"按直觉理解会得到相反结论"的地方。它们不写在 `SKILL.md` 里，因为逐条记住它们不会让稿子更好；但遇到行为不符合预期时，先在这里找。

**工作空间与绑定**

- **`.blueink/` 在项目目录里、不在技能目录里，并且在项目范围内向上查找。** 下级项目不会继承家目录的 `.blueink/`，`bind` 也拒绝直接把家目录作为项目根。换电脑或知识库改名后，用当前品牌的 `bind --force` 迁移路径并重建索引；路径失效或索引身份不一致时 `retrieve` 会拒绝旧结果，不会静默返回旧候选。
- **绑到品牌集合层会被直接拦住，不是告警。** 判定是结构启发式：子目录没有语料布局特征词、而是并列的若干名字就判为集合层。这条同时拦住"绑到四品牌总根"和"绑到现代汽车这一层"（它下面是 现代中国 与 现代 N 品牌 两个同级品牌）。确认是单一品牌时用 `--force`，此时会提示跨品牌污染检查将失效。
- **品牌改变的改绑会被拒，即使带 `--force`。** 换品牌请新建项目目录；当前品牌的知识库路径迁移可以显式确认。
- **未绑定时可以用 `绑定` 模式，或在给出附件时直接开启任务。** 无附件的生成、学习与定位模式没有可用证据边界，会被拒绝。

**附件与检索范围**

- **老师本次给的附件不受绑定根限制，但必须登记。** `open --attach <绝对路径>` 会记录路径、内容哈希与品牌归属；登记过的附件在审计 A2 里合法。**没登记就读，与越界读取无法区分**，审计会判违约——这是有意的。
- **`--evidence-boundary attachments` 是一条声明，不是一道锁。** 它声明"本次以附件为准"，审计据此检查有没有发生未申报的整库扩张。真的出现高影响缺口时，正常检索并在证据回执的 `gaps` 里写清缺什么，审计不会因此判违约。
- **知识库里的历史技能包默认不参与检索。** 有 `SKILL.md` / `AGENTS.md` / `CLAUDE.md` 的目录，整棵子树都标为 `历史技能产物`，品类标签清空。**按目录判定而不是按文件名**——技能包里的固定模板不在入口文件里，在它旁边的 references 目录里；只拦入口文件，模板照样会在"新闻稿 结构"这类检索里排到前列。审计这些技能包时才加 `--include-instruction-artifacts`。**注意这不是"经验总结不可用"**：老师手写的对接经验与传播红线仍是编辑策略轨的一等证据。
- **符号链接一律不跟随，且跳过项会被报出来。** 库里一条指向别的品牌目录的链接就足以让"自主检索根只有一个"失效。`index` 与 `doctor` 都会列出跳过了什么——静默跳过会让人以为那批资料已经进过索引。

**索引与内容抽取**

- **`content_status` 不是 `text` 的文件，正文没被读过。** DOCX 与 PPTX 会解包取正文；PDF、早期 DOC/XLS/PPT 格式和图片只登记元数据。不要把只有元数据的文件当成"已检索"。
- **`index --limit N` 是试跑预览，不写索引。** 它如果落盘，一次 `--limit 5` 就会把 186 条索引截成 5 条。
- **索引按内容哈希增量，不按修改时间。** 同步工具刷新过 mtime 但内容没变的文件不会重复入索引；内容变了而 mtime 没变的文件也照样能被发现。索引 schema 版本变化时自动全量重建，不混用两代记录。
- **源库里 `03-初终稿对比` 这类目录同时含初稿和终稿。** 阶段判定**文件名优先于目录名**：`【终稿】xxx.md` 即使在"初终稿对比"目录下也是终稿，可用作风格样本；`【初稿】xxx.md` 不能。风格轨只用终稿与成品参考；编辑策略轨反过来——它需要初终稿差异，所以初稿在那条轨上是必需的。

**知识库与品牌绑定**

- **未绑定不等于出错。** `status` 退出码 1 只说明这个项目还没绑定。两条正常出路：在访谈里问出知识库目录再 `bind`（老师还没有目录时加 `--create`），或者本次只用老师给的文件（`open --attach`）。**不要**因为未绑定就停下来报错。
- **`--create` 建出来的目录是空的。** `bind` 会明确提示检索会返回空。这时候不要开始写稿——先让老师把稿件丢进去，跑一次 `index`。空库上成稿等于全部靠模型即兴发挥，而那正是要消灭的东西。
- **本次品牌与绑定品牌不一致时不许自己选边。** `check-brand` 和 `open --brand` 都会拦。判定认简称（「理想」= 「理想汽车」），但「现代中国」≠「现代汽车」。把三条出路交给老师：品牌名写错了、换项目、或本次只参考指定文件。
- **`bind --force` 不允许换品牌。** 它只用于确认被集合层启发式误判的单品牌目录，或当前品牌换电脑／移动知识库路径。路径迁移会清空可重建索引并要求重跑 `index`，学习记忆与历史运行保留。
- **未绑定的运行里，任何目录都是越界。** 没有 `kb_root` 就没有"可自主检索的范围"，审计只认登记过的附件。缺料时向老师要，不要自己找。`meta.json` 中的 `bound: false` 与 `evidence_boundary: attachments` 记录这条边界。

**访谈**

- **`stopped_because` 必须指名维度。** 一句"信息已经足够"会被 A3 判违约——它对任何一次访谈都成立，因此什么都没说。写清评估的是事实安全、传播主线、信息权重、表达边界还是交付可行性中的哪几项。
- **表达边界最容易漏。** 发言人身份、语义温度、人称——这些错了要读完整篇才发现，然后整篇重写。QA 与演讲稿尤其如此。
- **同一个问题不许问两遍。** 归一化后相同就判违约。问前先读已有回答、看附件、`retrieve` 查一次索引；查一次几秒，问一次是老师的一轮注意力。
- **不许写信心百分比。** "当前信心 87%"会被判违约：它无法校准，但看起来像一次测量。

**联网与记忆**
- **联网前必须过 `official check-url`，退出码非 0 就不访问。** 白名单是主机级的，匹配规则是"等于该域名或是它的子域"。写入时会归一化：完整 URL 的路径被丢掉并告知，`www.` 前缀归一化到主域（否则 `https://lixiang.com/...` 会被自己的白名单拦住）。后缀伪装、用户名伪装、路径伪装、IP、通配符、非 http 一律拒绝。**搜索结果自称官网不算。**
- **独立事件必须引用真实运行。** `memory reinforce` 声明独立事件时会校验运行记录存在；不存在就拒绝。允许引用不存在的运行等于允许凭空制造"多个独立任务中重复出现"，而置信度完全依赖这个计数。同一场活动内的同向修改用 `--same-event`（只 +0.05）。
- **置信度上限 0.9，永不到 1.0。** 任何记忆都可能在下一个场景里失效；饱和到 1.0 会让"再来一个反例"失去意义。

**子智能体调用**

- **产回执的调用一律放前台。** 运行时对后台任务有等待上限（Claude Code 默认 600 秒）。跑满就被终止，回执没落盘等于这一段全部作废。取证和并行放后台的两个策略师实例都撞过这条线。
- **任务单必须给 `skill_root`。** 角色需要读 references（策略师要读《品类任务边界》）。不给它，子智能体只能在项目目录里逐个猜路径，可能连试七个不存在的路径才放弃。
- **A/B 的两个实例前台顺序跑。** 隔离要求的是上下文互不可见，不是并发。

**审计与测试**

- **`audit` 的 `incomplete` 不是 bug。** 运行中途中断很常见。只有"走到了那一步却违约"才判 `violated`。
- **审计通过不代表稿子好。** 它只验流程契约。
- **压力测试要做事件隔离。** 用历史真实需求测试时必须禁止检索到同一事件的历史终稿，否则测的是复述能力而不是生成能力。
- **登记在册的十一条品类是压力测试变量，不是验收边界。** 方法论对品类保持开放：遇到没登记过的交付物，靠访谈和证据判断"这份内容必须完成什么传播任务"，不新建固定骨架。
- **不要同时启用其它可被自然语言命中的文案技能。** 那类技能会绕过 `/blueink-suite` 这个总入口；BlueInk 运行以 `.blueink/runs/<run_id>/meta.json` 中的 `started_via` 为准。

## 记账的成本与留存期

这套记账是有成本的，如实承认：一次生成要落 `interview.json`、`program.json`、`delivery.md` 三份主智能体自己写的文件，加上各角色的回执。省掉它们能省一点时间，代价是这一稿一旦出问题就查不动——`audit` 只会报 `incomplete`，而那就是"不知道问题出在哪个 md"的原样复现。**记录不是仪式，它就是可定位性本身。**

**但记账必须能落得下来。** 回执规格过大时，"写审计材料"本身会变成主要耗时，最后一份都没写成——那比不记账更糟，因为它同时花掉了时间又没换来可定位性。回执的最小必要字段与体量上限见《编排协议》第四节；超出上限的内容不属于回执，属于本该被舍弃的过程材料。

成本里还有一项不能只说时间：**留存**。运行目录里有访谈原文、素材路径和交付正文。所以留存期是一条显式策略而不是"永远不删"——默认保留 90 天，且无论多旧至少保留最近 20 次运行（几个月才写一稿的老师纯按时间清会被清空，而那正是他定位问题时唯一的依据）。

```bash
$BLUEINK purge                          # 试运行，打印将删除哪些
$BLUEINK purge --apply                  # 真的删
$BLUEINK purge --keep-days 30 --apply   # 改留存天数
$BLUEINK purge --keep-runs 5  --apply   # 改"无论多旧至少保留几次"
```

`--keep-days` 与 `--keep-runs` 两条保护**取并集**：只有同时越过两条线的运行才会被删。所以 `--keep-runs 0` 才是"纯按时间清"，而那正是几个月写一稿的老师会被清空的那种配置。

删除范围只到项目内 `.blueink/runs/<run_id>/`，**永不触及源知识库**——源库只读是本技能最硬的一条承诺，清理留存不是它的例外。

## 常见误判

- **"检索返回空，索引质量有问题"** → 先跑 `doctor`。九成是 `kb_root` 路径失效或还没建索引。
- **"这条记忆明明有，为什么没生效"** → 两种常见原因：`confidence` 低于 0.65，只作推荐；`status: pending_confirmation`，还没确认生效。
- **"审计过了但稿子很差"** → 审计只验流程契约。稿子差要么是素材质量问题（承认它，靠反馈迭代），要么是编辑判断差（查 `adversary.json` 为什么没打出来）。
- **"跨品牌污染警报是误报"** → 检查 `workspace.yaml` 的 `brand`。绑到"现代汽车"这一层时，两个子品牌的名字互相都会被判为跨品牌。这通常是绑定层级不对；`bind` 会直接拦住这种绑定。
- **"审计说文件不存在，但我确实读过"** → 这项只在 `kb_root` 在本机可达时才检查。报出来说明路径写错了（多半是相对／绝对混用，或复制路径时丢了目录层级）——而写错的路径意味着这条来源没人能复核。
- **"每次都在问同样的问题"** → 绑定信息没落盘。查 `.blueink/workspace.yaml` 是否存在，以及当前工作目录是不是那个项目。
- **"某份资料明明在库里，检索不到"** → 三种可能：它的 `content_status` 不是 `text`（PDF、早期 Office 格式、图片只有元数据）；它在一个历史技能包目录里被标成了 `instruction_artifact`（`retrieve` 会报 `excluded_instruction_artifacts` 计数）；它被 `_iter_files` 跳过了（符号链接或不可读，`index` 与 `doctor` 都会列出跳过项）。三种都不是"索引质量差"，处置完全不同。
- **"官网也被 check-url 拒了"** → 看白名单里存的是什么。`official list` 显示的是归一化后的主机名；匹配规则是"等于该域名或是它的子域"，所以白名单里存 `ir.lixiang.com` 时 `lixiang.com` 不匹配。用 `official add --url lixiang.com` 补主域。
- **"reinforce 说独立事件必须引用真实运行"** → 这不是 bug。置信度完全依赖"独立任务重复出现"这个计数，允许引用不存在的运行就等于允许凭空把偶发偏好推到高置信度。同一场活动内的同向修改用 `--same-event`。

## 定位不了的时候

如果三步都做完仍然定位不到，说明这次失败的形态还没被建模。**把它记进方法论候选**，不要临时加一条规则去堵：

```bash
$BLUEINK memory add --scope methodology \
        --note "<现象、已排除的可能、缺哪一份证据才能定位>"
```

`methodology` 级只记录，不自动生效。多条证据指向同一个结构性缺口时再评审编排。**用一条新规则堵一个还没理解的现象，是规则清单膨胀的起点。**

## Gotchas（使用中捕获的纠正）

`python3 scripts/evolve.py --correct "<它哪里错了>"` 会把一条使用反馈原样追加到这里，同时写进 `EVOLUTION.md` 作为证据。

**它刻意不写进 `SKILL.md`。** 首读层是方法论；把每次使用中发现的具体现象往那里堆，几个月后它就会变成一份操作手册——而这套系统存在的理由恰恰是不做操作手册。这里是它们的正确落点：遇到行为不符合预期时，人本来就会来读这一份。

原样保留使用者的措辞，避免转述丢失当时的任务条件与可观察现象。是否形成正式约束，必须由独立评审决定。
