# 证据分轨取证

取证阶段读这里。

**先看边界，再看轨。** 本次证据从哪来是一个先于三轨的问题：

> **老师本次显式提供的附件，就是本次任务的证据。** `meta.json` 的 `evidence_boundary` 为 `attachments` 时，先只用附件完成任务；只有出现**会阻止成稿的高影响缺口或冲突**时，才按最小范围查询绑定知识库，并把缺的到底是什么写进 `gaps`。

**不为"可能有用的风格参考"主动展开整库研究。** 这条不是省算力，是防一类具体失败：老师附了两份文件并说"以附件为准"，系统仍然遍历了索引结构、全部同题材文件、同品类初终稿、业绩会速记和媒体深度稿，读掉几十万 token，最后一份回执都没落盘。**扩大检索范围看起来更严谨，实际是把一个已经封闭的证据边界重新打开，同时把成稿风险转移给了老师的时间。**

绑定品牌根约束的是**系统自主检索的范围**，不是老师的授权。附件不受绑定根限制，但必须登记（`open --attach`），否则审计无法区分"老师给的"与"自己越界读的"。

**这条边界关的是事实，不是风格。** 附件里通常没有"这位客户实际采用过的表达"——那只存在于绑定库的终稿里。所以纯附件任务允许取**少量**风格样本（按品类与时间近选，不做全库扫描），记进 `style_refs` 而不是 `facts`；审计的整库扩张提示会跳过 `style_refs` 里的路径，因为它不是事实来源。

下面三轨的判据，在需要向附件之外扩展时才用得上；纯附件任务用事实轨判附件、风格轨取一两份终稿。

核心结论一句话：**不要给所有资料排一条统一优先级。事实、风格、编辑策略需要的是不同的证据，判据也不同。**

把所有语料平铺进一个包，隐含假设是"越新的、越像终稿的越可信"。这个假设在事实轨上大致成立，在风格轨上勉强成立，在编辑策略轨上完全错误——编辑策略恰恰要看**初稿和终稿的差异**，而差异只存在于"不可信的初稿"里。

## 一 · 三条轨

### 事实轨

**判据：来源 + 发布日期 + 与本次任务的匹配度。**

优先级：**老师本次提供的附件 > 客户本次提供的需求材料 > 已确认的官方公开信息 > 本地库里的官方原文资产 > 历史成稿中被引用过的事实。**

- **历史成稿不能覆盖新事实。** 旧稿里的参数、职务、名称、排名一律视为可能过期。看到"某某副总裁"先确认这个人现在还在这个位置。
- 数字、日期、职务、产品全称、技术名称、资质表述，一律照抄来源原文。不换算、不四舍五入、不"统一格式"。
- 找不到来源的说法进 `gaps`，不进 `facts`。**"这个大家都知道"不是来源。**

### 风格轨

**判据：同品牌 + 同场景 + 时间较近 + 实际被采用。**

只看**终稿**。初稿的表达是被客户改掉的东西，把它当风格样本会学到已经被否掉的写法。源库里 `03-初终稿对比` 这类目录同时含初稿和终稿，必须分清再用。

- 同场景优先于同品类。一场用户大会的新闻稿和一场技术发布会的新闻稿，风格差别可能大于新闻稿和媒体供稿之间的差别。
- 时间较近优先于篇幅相似。领导换人、口径调整都会改变风格，半年前的稿子可能已经不适用。
- 风格样本是给写作者看语感的，**不是给它抄句式的**。任务单里给路径，不要把整篇塞进上下文。

### 编辑策略轨

**判据：初终稿差异 + 修改意见 + 多个独立案例中重复出现。**

这条轨的证据形态最特殊：它不在任何单一文件里，而在**文件之间的关系**里。

- 初稿删掉了什么、加了什么、顺序换成了什么——这才是客户真正的编辑判断。
- 一处修改是偶发，两处同向是巧合，三个独立任务里都这样才是规律。
- **单一案例的改动不能当规律。** 写进 `strategy_signals` 时必须列出支撑它的多个路径，只有一个路径的信号要标明这是单例。
- 反例和正例一样重要。发现某条规律在某类任务里不成立，把反例记进 `counterexample`。

## 二 · 跨品牌的唯一合法用法

**方法可以跨品牌复用，事实与品牌结论绝不可以。**

- 合法：「初终稿对比显示，客户普遍会删掉与主线无关的技术罗列」——这是编辑方法。
- 非法：「另一家客户喜欢把参数放在第三段」——这是别人的品牌结论。
- 非法：任何来自其他品牌的人名、产品名、平台名、话术、数字。

实际操作上不用记这条规则，因为**检索根只有当前品牌一个**，其他品牌的数据不在可达范围内。这条写在这里是为了说明：如果你在建设期（同时能看到四个品牌）做归纳，只能带走方法，不能带走结论。

## 三 · 官方公开信息：本地优先，条件触发

两个极端都不可靠。每次全网搜索：慢、噪声多，还会把媒体转述、旧页面、非官方内容当成事实。永远只用本地库：遇到新产品、领导变化、最新活动和时间敏感信息时必然过期。

**只在这四种情况查询已确认的官方渠道：**

1. 本次任务有明显时效性（刚发布、正在进行、下周举办）；
2. 本地事实缺失，或存在版本冲突；
3. 老师明确要求补充最新信息；
4. 素材里出现尚未进入本地库的新产品、人物或活动。

允许的官方来源写在 `workspace.yaml` 的 `official_sources`，首次绑定时由老师确认一次。

**每次联网前必须过这道机械闸，退出码非 0 就不访问：**

```bash
python3 scripts/blueink.py official check-url --url "<地址>"
```

判定规则只有一条：主机名等于白名单域名，或是它的子域。`lixiang.com.evil.cn`、`https://lixiang.com@别的主机/`、`https://某站/https://lixiang.com` 肉眼都像官网，而"看起来像"不构成来源。**搜索结果自称官网也不能跳过这一步。** 完整拒绝清单见《工作空间与索引》第八节。

- **官方资料只用于事实与时间线**，不用来推断客户内部偏好。官网上没写"我们喜欢什么风格"。
- 每次获取记录 URL、获取时间、页面日期。必要片段缓存在 `.blueink/index/cache/`，同一任务不重复抓取。
- **无法访问，或无法确认是官方来源时，标成缺口。** 不用普通媒体转述静默替代——媒体转述里的数字经常是记者换算过的。

## 四 · 冲突：一律上交，不许静默选边

四种冲突形态，处置相同：

| 形态 | 例子 |
|---|---|
| 本地 ↔ 官方 | 需求材料写 6 月 11 日，官网新闻中心写 6 月 13 日 |
| 新 ↔ 旧 | 去年财报的产能数字与本月官方口径不一致 |
| 文件 ↔ 文件 | 两份经验总结对同一红线说法相反 |
| 证据 ↔ 本轮要求 | 老师要求提某个数字，但库里这个数字标注为不可对外 |

处置：把双方原文、日期、来源都列进 `conflicts`，交主智能体。

**接下来分两种，别混。** 第四条方法论原则（"只解决会改变当前稿件的不确定性"）和"冲突必须上交"不矛盾，因为它们说的是不同的冲突：

- **会进入本稿事实表达的冲突** → 必须留下**可见记录**。要么在访谈里请老师裁决，要么由主智能体按证据强度裁决并写进 `program.assumptions` 与决策卡供老师否决。两条路都可以，**没有第三条**。
- **不会进入本稿的冲突** → 留在 `conflicts` 里备查，不追问。为一个本稿根本不写的数字去占用老师一轮，是在浪费他的耐心，而敷衍的回答比没有回答更危险。

**静默选一个是最严重的失职。** 不是因为选错的概率高，是因为选错之后没有任何人能发现——它把一个可见的分歧变成了一个不可见的错误。审计 A5 会在"证据里有冲突、而写作程序既没有 `assumptions` 也没有决策卡"时给出提示；它判不准老师到底裁决了没有，所以只提示不判违约——但那条提示出现时，就该有人回去看一眼。

## 五 · 检索纪律：一次任务读十几个文件，不是几百个

**纯附件任务的检索纪律是"不检索"。** 附件够用就直接落 `evidence.json`，`read_paths` 只有附件路径。下面这些是需要向附件之外扩展时才用的。

文件体积不等于上下文体积。索引可以有十几兆，一次任务只加载相关切片。

```bash
python3 scripts/blueink.py retrieve --run <run_id> --category "媒体观点供稿" \
        --query "交付 产能 平台" --track fact --limit 12
```

返回候选文件的路径、证据类型、时间、摘要、`content_status` 和命中理由，**不返回全文**。然后：

1. 按相关度从高到低读，读到能支撑本次主线的事实就停。
2. 不要"为了全面"把候选清单读完。读完一份就判断一次是否还缺。
3. 命中的每个文件都要落进回执 `read_paths`——这是事后定位问题的唯一依据。
4. 舍弃的候选也要落进 `discarded` 并写原因。

`--track` 可取 `fact` / `style` / `strategy`，索引会按三轨的判据分别排序：`fact` 优先原文资产与时间近的，`style` 只返回终稿与成品参考，`strategy` 只返回初终稿对比与经验总结。**不加 `--track` 时三轨混排，容易把初稿当风格样本，不推荐。**

## 六 · 两类不能当"已检索"的候选

- **`content_status` 不是 `text` 的文件，正文没被读过。** PDF、早期 DOC/XLS/PPT 格式和图片只登记了元数据（DOCX 与 PPTX 会解包取正文，是 `text`）。这些文件要么让老师在访谈里说明内容，要么标成缺口，**不能因为"索引里有这一条"就当成事实来源**。
- **历史技能包默认不在检索结果里。** 知识库里躺着混进来的写作技能包是常态（`04-经验总结原稿/xxx-writer/` 这类目录），里面是提示词和固定模板——**正是"结构固化：强制开篇铺垫行业背景"这条反馈的来源文件**。取出来当经验证据就是让外部提示词反向控制本次流程。`retrieve` 的返回值会报 `excluded_instruction_artifacts` 计数；确要审计这些技能包时才加 `--include-instruction-artifacts`。

第二条要特别小心一种误解：**这不是"经验总结不可用"。** 老师手写的经验总结、客户对接经验、传播红线，都是编辑策略轨的一等证据。被隔离的只有"由技能包生成的提示词与固定模板"，判定方式是它所在目录里有 `SKILL.md` / `AGENTS.md` / `CLAUDE.md`。
