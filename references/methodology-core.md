# 方法论内核

这份文件回答一个问题：**为什么这套系统必须长成现在这样。** 它不是操作手册。当你要判断某个新增设计是否违背核心观点，或者要向别人解释这套东西凭什么成立，读这里。

## 一 · 根因：一个前提性错误

一线反馈里反复出现四个症状：3MB 单包导致上下文溢出；多品牌语料集中存储导致交叉感染；知识库不知道是给人看还是给 AI 看，无法持续整理；自检只查禁词，老师真正要的来源标注反而没有。

但这四条都不是根因。它们是同一个前提性错误的四种表现：

> **把一线素材当成了可直接执行的规则。**

初稿、终稿、客户反馈、经验总结被平铺进同一个技能包，隐含的假设是"这些都是真理，装得越全，稿子越好"。于是：

- 因为都是真理，所以每次都该全读 → 上下文溢出。
- 因为都是真理，所以四个品牌的真理可以放在一起 → 交叉感染。
- 因为都是真理，所以整理的目标是"不遗漏" → 分类没有标准，越整越乱。
- 因为规则已经在包里了，自检只要查有没有违反 → 自检退化成查禁词。

**3MB 从来不是问题。** 真正的数据资产远大于 3MB：`【整理前】` 约 1.3GB，`【整理后】` 约 12MB。继续沿这条路做一个更大的技能包，必然重蹈覆辙。问题在于"一次任务加载全部"这个动作本身，而不在于总量。

## 二 · 正确的前提

素材不是规则，是**证据**。证据有强度、有时效、有适用范围。

| 旧前提 | 新前提 |
|---|---|
| 语料是规则，装进包里就生效 | 语料是证据，只有被本次任务命中才参与判断 |
| 品类对应固定骨架 | 品类规定必须完成的传播任务和边界，不规定段落顺序 |
| 品牌对应固定文风 | 品牌调性由当前可用的品牌证据决定，随证据更新 |
| 知识库越全越好 | 一次任务只需要十几个文件量级的相关切片 |
| 自检 = 查禁词和格式 | 自检 = 回答"这句话依据什么、观点从哪来、舍弃了什么" |
| 反馈 = 往库里加一条规则 | 反馈 = 修正证据权重、适用条件和编辑决策策略 |

由此得到核心观点：

> **blueink-suite 不是汽车文案规则库，而是一套证据驱动的编辑决策系统。它为每一次任务动态形成一份临时的"本次写作程序"，再交给写作子智能体执行。**

"临时"是关键词。写作程序只对这一次任务有效。它不沉淀成模板，不进化成新规则。会沉淀的只有一件东西：**做这类判断时该怎么判断**。

## 三 · 五个真正决定质量的判断

决定稿件质量的不是"套哪个模板"，而是这五个判断：

1. 写什么
2. 不写什么
3. 为什么
4. 各部分分配多少笔墨
5. 采用哪条叙事主线

规则库式的结构里没有任何一个位置负责这五个判断。品类骨架回答"按什么顺序写"，品牌声纹回答"用什么词"，事实白名单回答"能写哪些事实"，但"这次到底该讲什么、凭什么讲这个"是空的——只能由模型即兴决定，且不留痕迹。

全部机制都指向这五个判断：

- 逐轮访谈把它们从老师脑子里挖出来（老师知道答案，但不会主动说）。
- 三轨取证给它们提供不同强度的证据。
- 编辑策略师**显式**做出这五个判断，并写成回执。
- 写作程序把判断固化成写作者的输入。
- 编辑反方独立攻击这五个判断。
- 反馈归因员在老师推翻某个判断时，把它变成条件化记忆。

**做错这五个判断的任何一个，都能定位到具体角色和具体回执文件。** 这是这套设计最实质的性质——不是稿子一定更好，是稿子不好的时候能查。

## 四 · 为什么必须是主智能体加子智能体

多智能体不是为了显得先进。它解决三个具体问题，每一个都有对应机制。

**问题一：上下文过长导致规则失焦。**
子智能体各自持有独立上下文。取证阶段读进来的几十份原文，不会跟着进入写作阶段；策略阶段的论证过程，不会污染编辑反方的判断。规则全挤在同一个上下文里时，越靠后越失效。

**问题二：自证。**
同一个角色制定策略、执行策略、再证明策略正确，永远得不到有效审查。所以来源核验员和编辑反方都不读策略理由——理由会说服他们，而他们的价值恰在不被说服。

**问题三：无法定位。**
角色边界就是责任边界。事实错查取证，主线错查策略，表达差查写作，杜撰漏查核验。责任没有边界时，出问题只能整包重读。

但多智能体也带来一个真实风险，必须警惕：**把"文件层层嵌套"升级成"调用层层嵌套"。** 防它的办法有三条，都是硬的：

- 只有主智能体与老师对话，子智能体之间不互相调用。调用图是一层，不是一棵树。
- 角色按不可互相替代的认知责任拆，不按品类拆（会重造固定结构），不按品牌拆（会重造品牌技能包）。
- 确定性工作交给脚本，不交给 Agent。扫描、哈希、索引、路径校验、运行记录一律是代码。

一个角色应当独立存在，当且仅当同时满足三条：需要隔离上下文，否则会被前序结论污染；有独立的判断标准，不能由同一角色自证；出错后需要能够单独定位责任。**三条缺一条，就不该是独立角色。** 数量不是设计目标——六个是推导结果，不是先定的编制。

## 五 · 为什么访谈不能换成表单

老师不会主动交出那五个判断的答案。不是不配合，是**流程活在肌肉记忆里，说不出来**。问他"你要什么风格"，他会说"就正常公关稿的风格"；但给他看一段具体的稿子，他能立刻指出哪句不对。

所以：不能问"你想要什么"，要问"我倾向 A 因为……，但 B 会改变重心，你选哪个"。**带着判断提问，让老师做判别而不是做创作**——判别是人类可靠的能力，从零描述不是。

固定问卷会同时犯两个错：问一堆不会改变稿件的问题（浪费老师耐心，并让他学会敷衍），漏掉这次任务真正的风险点（因为它不在表单上）。所以停止条件是动态的：

> 如果下一个问题的答案仍有现实可能改变当前选定的传播方向、事实安全、核心信息权重或交付可行性，就继续；否则停止追问，记录剩余假设并进入写作。

七个决策域是主智能体的内部认知地图，不是要老师填的表。它们也不宣称穷尽——每轮都要再问一次"有没有一个它们没覆盖、但足以让这稿失败的特殊条件"。

## 六 · 为什么隔离靠物理而不靠提示词

跨品牌污染是最难缠的一类问题。用提示词写"不要读取其他品牌的资料"是无效的：一次检索误差就够了，而且失败是静默的。

**一个工作空间只绑定一个品牌知识库。检索根只有一个。其他品牌的数据根本不在可达范围内。**

这条选择付出了代价，要如实承认：技能本体不含任何品牌语料，复制技能不会带走绑定和记忆；换电脑或知识库改名后必须重新绑定。换来的是：新增品牌不改技能；品牌终止合作只归档工作空间；换领导只更新该项目的证据与记忆，通用方法论一行不动。

这正好回答了一线最尖锐的一条抱怨——"一旦品牌不再签约或者换了领导，之前积累的风格和规则全部都要推倒重来"。要更新的只有品牌工作空间里的证据。方法论不动，因为它从不包含品牌结论。

## 七 · 为什么绑定根不能延伸成"拒绝老师给的文件"

隔离靠物理，这条是对的。但它有一个容易越界的推论：**如果检索根只有一个，那是不是绑定根之外的任何文件都不该被读？**

不是。这两件事的主体不同：

- 绑定根约束的是**系统自己去找什么**。跨品牌污染的成因是系统在一次检索里误命中了别的品牌，而这类失败是静默的——所以要用物理边界防。
- 老师本次显式提供的附件是**他的授权**。它的来源强度高于任何检索结果：他知道这份材料是什么、为什么给、要用在哪。

把两者混成一条规则的代价是真实的：主智能体允许读老师附加的跨根文件，而审计规则把同一个路径判为越界。**运行逻辑与审计合同互相打架时，坏的不是其中一方，是那条把它们混起来的规则。**

正确的切分：附件不受绑定根限制，但**必须登记**（路径、内容哈希、品牌归属、`source: user`）。登记不阻止任何路径，它只让"老师给的"与"自己越界读的"在证据上可区分——没有它，审计只能二选一：要么放过真正的越界，要么把老师的授权判成违约。

这条推论还有一个方向：**老师说"以附件为准"时，附件就是本次的封闭证据边界。** 继续展开整库研究不是更严谨，是把一个已经封闭的边界重新打开，同时把成本转移给老师的时间。只有出现会阻止成稿的高影响缺口才最小范围扩展，并把缺口写出来。

**这条切分本身有一个已知代价，如实写出来：** 附件的品牌归属取自当前工作空间，不校验文件内容属于哪个品牌——校验它需要一张硬编码的品牌名表，而"新增品牌不改技能"是这套设计的承诺之一。所以老师如果附错了别家客户的材料，`open` 不会拦。拦它的是下游：来源核验员对正文做跨品牌实体核对，审计 A2 读它的结论。**入口不做内容判断，出口做**——这比在入口猜文件属于谁更可靠。

## 八 · 为什么学习必须带条件和反例

如果每次修改都直接更新方法论，系统会迅速过拟合：一次临时口径、某位领导的个人偏好、赶时间的妥协，都会被误学成长期规则。如果反馈只归档不生效，系统永远不会变好。

正确的中间态是**带置信度的条件化记忆**，而不是规则清单。

规则清单的失败模式是可预测的：它只增不减，越长越没人看，最后每条规则都在某些场合是错的，而系统无法判断"这次算不算"。条件化记忆则携带触发条件与不适用范围，可以被判断，也可以被反例修正。

反例出现时降低置信度或缩小适用范围，**不删旧结论**——冲突通常说明原来的适用条件写得太宽，而不是原来的观察是假的。

## 九 · 承认边界

一个诚实的方法论必须说清它做不到什么。

- **不能把低质量知识自动变正确。** 它能让错误可定位、可归因、可迭代，不能凭空提高证据质量。人工审核与未审核的素材都参与生成，取其精华，靠日常反馈反向迭代——但这意味着头几周的产出质量取决于素材质量。
- **不保证稿子一次就能用。** 第一质量指标是"老师把初稿改到可提交所需的修改量和修改时间明显下降"，不是"一次通过"。
- **不做品类认证。** 登记在册的十一条品类是压力测试变量，不是验收边界。方法论对品类保持开放。
- **不承担改稿编排、版本回退、Word 排版、配图、品牌文档模板。** 第一版只负责文案生成。
- **不承诺自然语言自动触发。** 只认 Claude Code 显式入口；默认 `/blueink-suite`，同名冲突时使用规范化入口。

最后一条最容易被当成缺陷，其实是选择：一个"有时会自动生效、有时不会"的入口，比一个必须显式调用的入口更难排查。**能被确认的行为，比看起来更聪明的行为更有价值。**
