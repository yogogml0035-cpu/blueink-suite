# 逐轮访谈协议

访谈的目标不是收集信息，是**把五个编辑判断（写什么、不写什么、为什么、笔墨怎么分、走哪条主线）从老师的肌肉记忆里挖出来**。

进入访谈前读这里。不知道下一个问题该问什么时读这里。怀疑自己在问无效问题时读这里。

下文 `$BLUEINK` 表示当前智能体已经按当前 macOS／Windows 环境解析并试跑过的绝对 CLI 命令，不是让老师原样输入的 shell 变量。

## 一 · 一条规则先立住

**每轮只问一个问题。** 不是"最多一个"，是恰好一个。

理由不是礼貌，是信息论上的：一次问三个问题，老师会挑最容易的那个答，剩下两个变成沉默，而你无法区分"他觉得不重要"和"他漏看了"。一次一个，每个回答都是干净信号。

## 二 · 问前必做的三件事

1. **先读已有回答。** 老师上一轮说过的、需求材料里写着的、`workspace.yaml` 里绑定过的，都不许再问。重复提问是访谈失败最常见的形态，它的代价是老师开始敷衍，而敷衍的回答比没有回答更危险。审计会把归一化后相同的两个问题直接判为违约。
2. **先看附件。** 老师本次给了附件时，答案九成在附件里——先读完附件再决定要不要问。
3. **先查索引。** 附件之外，能在品牌知识库里查到的先查再问：

```bash
$BLUEINK retrieve --query "<你想问的那件事>" --limit 8
```

**"附件或索引里已有的内容"永远不构成一个合法问题。** 查一次的成本是几秒，问一次的成本是老师的一轮注意力——而他的注意力总量决定了这次访谈还能问几个真问题。

## 三 · 怎么构造这一个问题

问题的质量标准只有一条：**它的两种可能答案会导向不同的稿子。**

用这个模板检验：

> 如果老师回答 X，我会怎么写？如果回答 Y，我会怎么写？

两种写法一样 → 这不是有效问题，扔掉，找下一个。

**优先形态：带判断的二选一。** 不要空问"你希望什么风格"，要问：

> 我目前更倾向从用户价值切入，因为你给的素材里赛事过程比参数更完整；但从技术突破切入会把重心移到平台能力上，更适合面向行业媒体。你选哪一个？

这个形态同时做了四件事：暴露你的判断（老师可以直接否掉，省一轮）；给出理由（老师能看出你是否读懂了素材）；说明代价（老师知道选择意味着什么）；把创作题变成判别题（人类可靠的能力）。

**次优形态：指出矛盾请裁决。**

> 需求材料里写的是 6 月 11 日发布，但官网新闻中心那条是 6 月 13 日。以哪个为准？

**要避免的四种形态：**

| 形态 | 例子 | 为什么坏 |
|---|---|---|
| 空问偏好 | "你希望什么风格？" | 老师只能答"正常公关稿的风格"，零信息 |
| 复述式确认 | "所以你是要一篇新闻稿，对吧？" | 已知信息，浪费一轮 |
| 打包多问 | "读者是谁？渠道是哪里？篇幅多少？" | 违反一问原则，且会得到一个只答了一半的回答 |
| 无后果提问 | "这次活动的天气怎么样？" | 答案不改变任何写法 |

## 四 · 七个决策域：内部认知地图，不是问卷

这七个域用来定位"我现在缺什么"，不是逐项询问的清单。

**这七个域是内部认知地图，不是要老师填的表。** 不要把这张表输出给老师，也不要在 `interview.json` 里为七个域逐一填状态——只记录本轮实际用到的那一两个。没查过的域不写，比写一个"已知"诚实：写"已知"是在断言你确认过。

**不要把七个域渲染成状态表交给老师。** 状态表会占用注意力，却不能直接改进稿件判断。

| 决策域 | 核心判断 | 缺失时的典型后果 |
|---|---|---|
| 传播关系与目标 | 谁在说、对谁说、希望对方发生什么认知或行动变化 | 写出一篇"又发了个稿"的东西 |
| 场景与交付合同 | 什么时间、场合、渠道，以什么形态、篇幅和格式交付 | 形态不对，接收方没法直接用 |
| 事实与证据边界 | 哪些内容可以写成事实，来源、时效、冲突和缺口是什么 | 杜撰或用过期事实 |
| 编辑决策空间 | 主线、素材取舍、信息预算、观点层级和可能的 A/B 方向 | 素材堆砌，没有主张 |
| 身份与表达边界 | 品牌、发言人、语义温度、历史偏好及本次临时调整 | 换成任何一家车企都成立 |
| 风险与裁决权 | 哪些内容不能说，哪些冲突需要谁决定，审批链关注什么 | 稿子写完卡在审批 |
| 成功与验证标准 | 老师凭什么判断可用，哪些问题会导致方向性返工 | 交付后才发现方向错 |

**不要求每类任务都填满。** 一条短社会化文案未必需要完整时间线；新闻稿对事实与时间极其敏感；QA 更需要明确发言边界和可能的追问；演讲稿更依赖发言人、场合和听众关系。要求所有任务满足同一套完整字段，会让访谈越来越像表单，也会诱导你为了"填满门槛"追问大量不改变稿件的问题。

每个域标记五种状态之一：

| 状态 | 含义 | 处置 |
|---|---|---|
| `与本稿无关` | 这类任务不需要它 | 不问 |
| `已知` | 已从回答或证据中确定 | 不问 |
| `暂定假设` | 你做了判断，但老师没确认 | 不问，但必须进写作程序的 `assumptions` |
| `存在冲突` | 两个来源／两条要求互相矛盾 | 候选提问对象 |
| `高影响缺口` | 缺它会改变事实、主线或品牌表达 | 候选提问对象 |

只在 `存在冲突` 和 `高影响缺口` 里挑**最可能改变稿件**的那一项提问。

## 五 · 每轮必问的开放问题

七个域不宣称穷尽。每轮在心里再问一次：

> 当前是否存在一个未被这七个域覆盖、但足以让这篇稿件失败的特殊条件？

真实例子：领导讲话有严格时长限制；活动流程决定串词的插入点；媒体署名关系决定这篇能不能用第一人称；平台有字数或话题标签限制；这个时间点撞上行业负面事件；同一活动另一家客户也在发稿。

有就为本次任务**临时**增加一个观察维度，不永久扩充所有任务的问卷。

## 六 · 什么时候停

动态充分性判断，不是固定门槛：

> **如果下一个问题的答案仍有现实可能改变当前这一稿的事实安全、传播主线、信息权重、表达边界或交付可行性，就继续访谈；否则停止追问，记录剩余假设并进入写作。**

这五个维度是**判据**，不是问卷：

| 维度 | 下一问可能改变什么 |
|---|---|
| 事实安全 | 哪句话能写成事实，来源、时效与冲突怎么处理 |
| 传播主线 | 这一稿的核心主张与切口 |
| 信息权重 | 哪部分多写、哪部分简写或舍弃 |
| 表达边界 | 谁在说、用什么语义温度、品牌与发言人身份的边界在哪 |
| 交付可行性 | 篇幅、形态、格式与时间上能不能真的交出去 |

**表达边界最容易被漏掉，而它的返工代价最高。** 事实错老师能一眼看出来，语义温度不对、发言人身份用错、把媒体署名稿写成品牌自述——这些要读完整篇才发现，然后整篇重写。QA 与演讲稿尤其如此：同一批事实，换一个发言人身份就是另一份稿子。

**停止时必须写清评估的是哪一维。** `stopped_because` 里一句不指名的"信息已经足够"对任何一次访谈都成立，因此它什么都没说；审计会直接判违约。正确的写法指名维度和结论：

> 剩余未知项都不会改变事实安全与信息权重：交付合同老师已给定，发言人身份由《指引》封闭，缺的两项是活动现场细节，不进正文。

配套三条：

- **不显示信心百分比。** "当前信心 87%"无法校准，只制造精确感——而老师会照着它决定要不要再补材料。判断标准是行为，不是数字。审计会把这类数值判为违约。
- **只评估本稿实际要用的事实和判断**，不追求把所有背景都问清楚。允许保留不影响当前方向的未知信息。
- **老师回"你决定"时可以裁决**，但这个假设必须显式进入写作程序，并在决策卡里可见。裁决本身不是问题，裁决而不留痕才是。

反向也要防：**不许过早开写。** 事实不清、主线未定、品牌边界不明就动笔，是把风险转移给老师。事实、品牌边界和明确冲突不能靠创造性解决——创造性该发生在编辑策略阶段（多条主线、不同结构、A/B 方向），不该发生在事实层。

## 七 · 面向非专业用户时

默认服务专业文案老师：可以直接使用行业术语，减少基础解释，允许老师覆盖系统判断。

但对方明显不是专业文案时（说不清品类、说不清读者、把渠道当品类），自动提高解释与引导强度：把术语换成"这份东西是给谁看的、你希望他看完做什么"这类问法，并承担更多编辑判断——同时把承担了哪些判断写进决策卡，让对方至少知道系统替他决定了什么。

**默认对象的差别只体现在访谈深度、术语、推荐力度和当前智能体替用户承担多少编辑判断上，不体现在方法论上。**

## 八 · 访谈记录

每轮追加一条到 `.blueink/runs/<run_id>/interview.json`：

```json
{
  "rounds": [
    {"n": 1, "question": "问出去的原话", "domain": "编辑决策空间",
     "state_before": "高影响缺口", "checked": ["已有回答", "附件", "索引"],
     "answer": "老师原话", "changed": "这个回答改变了什么判断"}
  ],
  "domains": {"事实与证据边界": "存在冲突", "编辑决策空间": "暂定假设"},
  "ad_hoc_domains": [{"name": "领导讲话时长限制", "why": "..."}],
  "stopped_because": "剩余未知项都不会改变事实安全与信息权重：交付合同老师已给定，发言人身份由《指引》封闭",
  "residual_assumptions": ["进入写作程序的暂定假设"]
}
```

**`domains` 只写本次实际用到的维度。** 不为字段完整性填满七个域；`ad_hoc_domains` 没有临时维度时不写。

`checked` 记的是**问这一轮之前查过哪里**。它的作用是让"不重复询问已知事实"这条纪律可复核：事后发现某个问题的答案本来就在索引里，能一眼看出是没查还是查了没查到。

`changed` 字段是这份记录的价值所在。**如果连续两轮的 `changed` 都是空的，说明你在问无效问题**——立刻停下重新定位缺口，不要靠继续追问碰运气。

审计的 A3 机械守住四条：每轮 `question` 只含一个问题；归一化后相同的问题不许出现两次；连续两轮 `changed` 为空判违约；`stopped_because` 必须指名五个维度中至少一个，且不许出现伪精确的信心数值。**同一话题的不同追问不算重复**——那类追问恰恰是访谈该做的事。
